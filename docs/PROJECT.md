# 问题与实现

用可解释规则决定哪些请求上高成本模型，再把同一题目的low、high、route结果放到同一分母下比较。规则只读取请求文本与约束，不读取题号、答案键或人工期望档位；route独立调用所选模型。

| 模块 | 作用 |
|---|---|
| `router.py` | 文本、字段数、多材料与比较线索决定槽位 |
| `contract.py / ledger.py` | 尝试开始前登记；成功、失败和未知状态分开保存 |
| `pricing.py` | 从平台usage按冻结单价折算；未知传播为null |
| `runner.py` | 纯标准库urllib调用、单次上限、清单、评分和台账 |
| `m2_batch.py` | 交错编排三组、批准身份复核、费用与异常停线 |
| `m2_reconcile.py` | 对照父尝试和子事件，保留未执行项及未知费用 |
| `grade.py` | JSON字段/类型、拒答短语、摘要长度与覆盖检查 |
| `tools/review_m2.py` | 人工输入身份校验与AND合成，本次未用collect/derive |

冻结规则后运行；规则变更建立新版本，保留旧请求、答案、费用和旧评分。材料均为自造样例。M1是开发调试对照，M2是独立测试集，二者不合并为一个质量样本。

未知费用即停止。平台4xx、子进程异常等错误也可停止；没有自动重试与补跑。软件预算是停线条件，不是平台支付硬限额。

本项目没有训练模型，也没有接入通用路由框架或缓存平台。公开程序可用本地桩验证实现和失败路径；真实模型能力需要单列真实样本证据。
